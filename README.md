# Pixgin

Pixgin membuat poster kampanye utuh langsung dari prompt pengguna dengan Agent Free atau Agent Pro. Alur website selalu memakai **Poster Utuh - langsung dari Agent** tanpa pilihan Desain editable atau prediction planner tambahan, termasuk untuk proyek lama yang sebelumnya memilih mode editable. API dan dokumen editable lama tetap tersedia untuk kompatibilitas; hasil poster dapat dibuka lewat **Edit desain** sebagai satu layer gambar dengan elemen baru di atasnya.

Identitas teknis lama untuk cookie, local storage, tabel, dan bucket Supabase sengaja tetap menggunakan nama `layera` agar sesi dan data yang sudah ada tetap kompatibel setelah pergantian merek. Alamat bantuan lama juga tetap aktif sampai alamat Pixgin yang baru dikonfirmasi.

Di Koleksi, penyimpanan gambar dikonfirmasi setelah server berhasil menyimpan daftar desain. Refresh sebelum perubahan tersimpan memunculkan pengingat. Setelah login kembali, daftar Koleksi dimuat dari Supabase; server menyegarkan sesi/data dan memakai conditional write pada `updated_at` agar instance lama tidak menimpa simpanan baru. Tidak ada perubahan schema Supabase yang diperlukan. Untuk menghapus, centang desain atau gunakan **Pilih semua**, lalu klik **Hapus terpilih**. Konfirmasi menampilkan jumlah desain yang akan dihapus beserta semua versi editnya. Hasil gambar di proyek tetap tersedia. Penghapusan disimpan sekaligus ke akun sebelum kartu dihilangkan; jika penyimpanan gagal, desain dan pilihannya tetap tersedia untuk dicoba kembali.

Paket Gratis menyediakan **1 gambar kualitas Standar dan 3 edit AI setiap minggu**, dengan reset Senin pukul 00.00 UTC. **Pixgin Pro Rp139.000/bulan** menyediakan generasi dan edit AI tanpa batas, semua kualitas, dan pilihan 1 atau 10 gambar per permintaan. Penggunaan tetap dicatat di server; nilai limit/remaining `-1` dan `credits.unlimited: true` menandai akun Pro tanpa batas kredit. Integrasi pembayaran belum aktif. Hasil diberi nama netral `Variasi 01` hingga `Variasi 10`. Proyek baru dapat mengunggah maksimal lima gambar produk dan satu logo. Logo diberikan sebagai referensi terakhir kepada AI. Poster lama dapat dibuka di editor sebagai satu latar terkunci; tidak ada ekstraksi objek otomatis.

Klik **Edit desain** pada hasil atau Koleksi untuk memindah/resize/rotasi objek, mengedit teks, mengatur layer/grup, undo/redo, autosave, menyimpan versi, atau mengunduh PNG. Edit manual tidak memanggil AI dan tidak memakai kuota. Hapus latar AI adalah tindakan opsional yang memakai satu edit AI hanya jika berhasil; upload asli tetap bisa dipulihkan. Huruf dalam gambar logo raster diubah dengan mengganti aset logo.

Editor manual memerlukan [setup Supabase desain](supabase/EDITABLE-DESIGNS.md); generasi poster utuh tetap tersedia tanpa setup tersebut. Dokumen, revisi, dan versi disimpan terpisah dari state akun; gambar tetap privat. Editor React/react-konva dimuat terpisah dari `public/editor.js` dan `public/editor.css` hasil build. PNG/JPG/preview memakai renderer yang sama pada resolusi artboard, setelah aset/font siap, tanpa selection handle. Jumlah layer mengikuti objek dalam dokumen, tanpa batas jumlah tetap. Batas sumber daya tetap berlaku: dokumen tervalidasi 500 KB, kedalaman grup 5 level, dan artboard maksimum 4096 px per sisi / 8 megapiksel; kapasitas praktis juga bergantung pada browser dan ukuran aset.

Panel Layer menampilkan seluruh objek beserta isi grup, dengan urutan teratas sebagai objek paling depan di masing-masing grup. Klik layer atau objek di kanvas untuk memilihnya, gunakan checkbox/Shift untuk multi-pilih, ↑/↓ untuk urutan, ikon mata/kunci untuk visibilitas dan penguncian, serta ikon pensil untuk mengganti nama. Layer di dalam grup bisa dipilih dan diedit sendiri; kunci pada grup melindungi seluruh isinya. Pengelompokan memerlukan objek dengan parent yang sama. Badge promo dan stiker adalah grup shape + teks asli yang tetap dapat diedit. Ungroup mempertahankan transformasi dan opasitas.

Sistem layer menggunakan kembali React/Konva yang sudah ada, tanpa dependensi atau layanan AI tambahan. Gambar AI yang sudah utuh tetap menjadi satu layer gambar; teks atau logo yang sudah tertanam di dalamnya tidak dianggap sebagai objek terpisah. Pengguna dapat menambahkan gambar, logo transparan, teks, badge, stiker, dan bentuk di atasnya. Format dokumen versi 1 dan penyimpanan lama tetap kompatibel; perubahan layer dinamis ini tidak memerlukan SQL tambahan di luar setup desain yang sudah ada.

Setiap halaman Pixgin dibuka ulang, sesi sebelumnya diakhiri dan pengguna diminta masuk kembali. Hasil gambar baru disesuaikan dengan rasio poster tanpa memotong konten sumber; jika model menghasilkan rasio yang berbeda, sisi kosong diisi dengan latar buram dari gambar yang sama. Pratinjau juga menampilkan keseluruhan gambar. Hasil lama yang sudah terpotong saat dibuat tidak dapat dipulihkan otomatis dan perlu digenerasi ulang.

Frontend memakai `index.html`, `public/styles.css`, dan komponen TypeScript terurut di `public/components/`. `public/app.ts` menyediakan helper awal; `tsconfig.browser.json` menggabungkan seluruhnya menjadi satu classic script `public/app.js` saat build. Jangan mengedit JavaScript hasil build secara langsung atau mengubah urutan file komponen tanpa memeriksa inisialisasi browser.

Untuk menjalankan lokal, lihat [NODE-DEPLOYMENT.md](NODE-DEPLOYMENT.md). Jalankan `npm run check`, `npm test`, dan `npm run build` sebelum mengirim perubahan.

Jika Replicate menampilkan **Request was throttled / HTTP 429**, adapter menunggu `Retry-After` atau waktu reset pada pesan lalu mencoba ulang (maksimal 3 retry dan anggaran tunggu hingga 90 detik, dibatasi timeout provider). Cancel tetap bekerja selama menunggu. Respons billing/402, error server, dan koneksi yang putus tidak diulang otomatis agar tidak berisiko membuat prediction ganda. Saldo rendah dapat membuat batas rate limit lebih ketat; periksa saldo/billing di akun Replicate. Generasi tidak memakai `REPLICATE_LAYOUT_MODEL` lagi; environment lama tersebut boleh dihapus. Sepuluh variasi tetap membutuhkan sepuluh prediction gambar, bukan satu.

`npm run test:editor` menjalankan acceptance test desktop/mobile di Chrome dengan provider mock dan akun memori. Set `CHROME_PATH` jika Chrome tidak berada di lokasi default Windows. Tes ini menguji drag, teks, export, autosave/retry, konflik revisi, dan reopen tanpa mengakses produksi atau memakai kredit AI.

Pendaftaran baru membutuhkan kode verifikasi email Supabase sebelum pengguna bisa masuk. Sebelum merilis, aktifkan **Confirm email**, pasang template kode, dan konfigurasi SMTP publik sesuai [panduan verifikasi email](supabase/EMAIL-VERIFICATION.md). Tidak memerlukan SQL tambahan; akun lama tetap bisa masuk seperti biasa.
